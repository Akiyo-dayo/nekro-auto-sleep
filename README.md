# NekroAgent 自动睡眠插件

为每个会话提供独立的拟人化睡眠周期，无需修改 NekroAgent 核心代码。
同时兼容 Akiyo 版 (`Akiyo-dayo/NekroAgent_ByAkiyo`) 与原版上游 (`KroMiose/nekro-agent`)。

## 功能

- **定时入睡与随机起床**：默认每晚 23:00 静默入睡，次日 06:45–08:30 之间随机自然醒
- **由 LLM 判断的叫醒协议**：呼叫→固定提示（不经 LLM）→**第二次触发直接进 LLM**，
  由它读懂对方到底要不要叫醒：要就正常回复，不要就静默睡回去。
  插件不做关键词猜测；每夜提示次数与冷却上限，防止凌晨被刷屏
- **唤醒后上下文连贯**：整夜消息照常入库，叫醒提示进历史，被叫醒后每一轮都能拿到
  「几点就寝、被谁叫醒、醒了多久、夜里的消息是睡着时收到的」
- **夜间定时任务照跑**：用户排的定时提醒在睡眠期间仍会执行，Bot 知道自己是「夜里值班」，
  处理完继续睡；值班时长按半睡计入质量。也可整夜屏蔽
- **重启自愈**：启动时对账所有频道，补结算错过的自然醒、补入睡错过的夜晚
- **主动睡下**：Bot 可调用 `resume_sleep` 工具重新入睡
- **空闲自动睡回**：被叫醒后无新互动自动静默睡回（默认 10 分钟）
- **可解释的睡眠质量**：100% = 睡满目标时长且没被打扰，睡得更久会超过 100%；
  每一项扣分都会随结算一起存下来备查
- **自然醒播报**：默认每次自然醒都播报，可切换为「仅当夜里被打扰过」或「从不」
- **按频道 / 按人设的作息**：同一份全局配置之上，可以只把某个群或某个人设的作息挪走
- **运维指令**：`/sleep status` 直出昨夜评分的每一项，`/sleep now|wake|skip` 手动介入

## 安装

把 **`nekro_auto_sleep/`** 这个目录（不是仓库根目录）复制到 NekroAgent 的 `plugins/external/` 下：

```
plugins/external/nekro_auto_sleep/
├── __init__.py
├── models.py
├── schedule.py
├── quality.py
├── engine.py
├── persistence.py
└── runtime.py
```

重启 NekroAgent 后在插件管理页面启用「自动睡眠」插件。

## 从 v1 升级

插件配置是**按字段持久化**的，所以升级后新的默认值只对全新安装生效，老装机保留原值。
有一项必须手动改：

| 配置项 | v1 默认 | v2 默认 | 不改会怎样 |
|---|---|---|---|
| 睡眠质量下限 | `60` | `20` | v2 的量程是 20–110，下限 60 会把所有糟糕的夜晚一律夹到 60，**看起来就像分数不动**——正是 v1 那个 bug 的症状 |
| 质量稳定扰动幅度 | `4.0` | `2.0` | 分数现在本就随实际情况浮动，4.0 的随机量偏大 |

插件启动时会对下限过高发一条 WARNING，`/sleep status` 也会把它显示出来，
并在分数真的被夹住时标注「原始分 X，被下限 Y 夹住」。

已删除的配置项（`NEAR_WAKE_RATIO`、`AFFIRMATIVE_KEYWORDS`、`NEGATIVE_KEYWORDS`、
`UNCLEAR_ANSWER`、`TIMER_AGENT_WAIT_TIMEOUT_SECONDS`）会在下次保存配置时自动消失，不用手动清。

## 配置

所有配置项均支持 WebUI 中文界面。

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| 启用自动睡眠 | `true` | 总开关 |
| 时区 | `Asia/Shanghai` | IANA 时区名称 |
| 入睡时间 | `23:00` | 每日自动入睡时间（HH:MM） |
| 起床时间范围（起始 / 结束） | `06:45` / `08:30` | 随机起床区间 |
| 起床随机粒度 | `1` 分钟 | 候选起床点间隔 |
| **接近起床提前量** | `60` 分钟 | 距计划起床这么久时提示语切换为「还没起床」 |
| 叫醒确认窗口 | `180` 秒 | 提示发出后多久内的回答算数 |
| **紧急关键词** | 空（关闭） | 可选的关键词直通，开启后有误判风险 |
| **叫醒提示语 / 接近起床提示语** | 见工作流程 | 可改写，`{persona}` 会替换为人设名 |
| **谁的回答算数** | `offeree` | `offeree`=只认被问的人 / `anyone`=群里任何人 |
| **每夜最多提示次数** | `3` | 超出后整夜静默 |
| **提示冷却** | `20` 分钟 | 两次「要叫醒吗」之间的最短间隔 |
| **拒绝后静默时长** | `30` 分钟 | 有人说了不用叫之后的安静期 |
| 历史记录模式 | `preserve` | `preserve`=夜间消息与叫醒提示都入库 / `strict`=完全拦截不留痕 |
| 呼叫关键词 | `醒醒,起床,在吗` | 触发叫醒的关键词（逗号分隔） |
| 默认人格名 | `Bot` | 取不到预设名时的回退名 |
| 提前叫醒空闲超时 | `10` 分钟 | 被叫醒后无互动的睡回时间 |
| **起床播报策略** | `always` | `always` / `if_disturbed` / `never` |
| 离线补发宽限期 | `120` 分钟 | 重启后补发自然醒播报的最大延迟，超时静默结算 |
| **启动装载活跃天数** | `14` | 启动时装载最近多少天有消息的频道 |
| 维护循环间隔 | `15` 秒 | 后台检查间隔 |
| **夜间定时任务策略** | `run` | `run`=照常执行 / `block`=只入历史不执行 |
| **夜间值班计入时长** | `3` 分钟 | 每次夜间任务按此计入质量（其中一半算损失的休息） |
| **目标睡眠时长** | `0`（自动） | 质量 100% 的基准；0 表示自动取起床窗口中点 |
| 睡眠质量下限 / 上限 | `20` / `120` | 夹取区间。下限从 60 降到 20，让糟糕的夜晚看得出来 |
| 质量稳定扰动幅度 | `2.0` | 随机扰动范围；分数现在本就随实际时长浮动，不再依赖它制造变化 |

## 运维指令

| 指令 | 权限 | 说明 |
|---|---|---|
| `/sleep status` | 高级用户 | 当前状态、今夜提示次数、**上一夜评分的每一项** |
| `/sleep now` | 超级用户 | 立刻入睡（从此刻开始计时，不是从配置的就寝点） |
| `/sleep wake` | 超级用户 | 立刻起床并结算，会照常播报 |
| `/sleep skip` | 超级用户 | 今晚不睡，明晚恢复 |
| `/sleep set <字段> <值> [scope]` | 超级用户 | 设置作息覆盖，`scope` 为 `channel`（默认）或 `preset` |
| `/sleep unset [scope]` | 超级用户 | 清除覆盖 |

`set` 的字段：`tz`（IANA 时区）、`bed`（就寝 HH:MM）、`wake-start`、`wake-end`。
值会先校验再落库，写错时间或时区会直接报错而不是留到半夜才发作。

`/sleep status` 的样子：

```
【阿绫 · 睡眠状态】
作息：23:00 → 06:45~08:30（Asia/Tokyo）　覆盖：timezone=本频道
当前：睡着（23:00 就寝，计划 07:24 起床，已睡 4 小时 12 分钟）
今夜：已提示 1/3 次，静默至 02:47
上一夜：103%，睡了 8 小时 41 分钟
　　基准 8.68h · 覆盖 100.0 · 碎片 -0.0 · 呼叫 -0.0 · 叫醒 -0.0 · 整夜无扰 +3.0 · 扰动 +0.3
本夜记录：没理会的呼叫 1 次，真被叫醒 0 次
```

## 作息覆盖

优先级 **本频道 > 人设 > 实例 > 全局配置**，逐字段生效——只改就寝时间不会连时区一起钉死。

- **按频道**：跨时区的群不用再跟着全局时区睡觉
- **按人设**：换人设就换作息，和这个项目里记忆/好感按人设隔离是同一套思路
- **按实例**（仅 Akiyo fork）：多账号部署时每个实例可以有自己的作息

`/sleep status` 会标出每个字段是从哪一层来的。频道与人设两级存在插件自己的存储里（不建表），
实例级读的是宿主的实例配置覆盖。

### 多实例共群

fork 的 `chat_key` 自带实例段（`onebot_v11-inst1-group_123456`），所以同一个群里的两个账号
天生是两条独立的记录：**各自的睡眠状态、各自随机抽的起床时间、各自的质量评分**。
起床点的随机种子取自 `chat_key`，两个实例即使配置完全相同也会抽到不同的分钟数。

但有一处以前是被拍平的：`ScopedPluginConfig` 靠适配器在入站时写的 contextvar 解析实例级配置，
而**维护循环是后台任务、没有入站上下文**——于是不管运营给两个实例配了什么作息，
后台一律读全局值。现在改成按 `chat_key` 查到频道的 `instance_key`、显式调
`resolve_scoped_config` 解析，配置和快照都取这个实例的那一份。

上游是单实例、也没有 `scope.py`，能力探测不到时整段回落到全局配置，行为与改动前一致。

## 工作流程

### 正常睡眠

```
23:00 → 静默入睡（不发消息）
       ↓ 夜间普通消息：入库但不触发 LLM（strict 模式下完全不入库）
06:45-08:30 → 随机时间自然醒 → 【{persona}已起床：昨日睡眠质量 N%，睡眠时长 X】
```

### 叫醒流程

```
用户有效呼叫 → 【{persona}已经睡了 要叫醒{persona}吗？】(不经 LLM，preserve 模式下进历史)
       ↓ 被问的那个人的下一条消息（不论说了什么）
       → FORCE_TRIGGER 进 LLM，注入告诉它「这条是对方的回答，先判断要不要叫醒你」
            ├─ 对方确实要叫醒 → 正常回复，Bot 醒着（还带睡意）
            └─ 对方并不需要   → 调用 resume_sleep，**一个字都不发**，静默睡回去；
                              这次呼叫降级成「没理会的呼叫」，睡眠段也不算断开
       ↓ 10 分钟无新互动 → 静默睡回
       ↓ 聊完之后 Bot 再调用 resume_sleep → 【{persona}已睡下】
```

**判断交给 LLM，插件不做关键词匹配。**「要」「算了你睡吧」「我要睡了」「你在哪」
一律进同一条路：模型带着上下文读这句话，比任何词表都准。
手写词表试过一版，`要`/`好`/`对` 在中文里太常见，「我要睡了」会被读成同意、
「对不起吵到你了」也会——这类误判无法靠加词修好。

唯一保留的关键词通道是**紧急词直通**（默认关闭）：开启后消息里出现这些词、
且是冲着 Bot 来的，就跳过提问一步叫醒。

被忽略的呼叫照常记进当晚记录并扣质量分——限流只是不再回话，不是当没发生过。

距计划起床 60 分钟内，提示语改为 **【{persona}还没起床 要叫醒{persona}吗？】**。

### 夜间定时任务

默认 `NIGHT_TIMER_POLICY=run`：睡眠期间的系统消息照常放行。宿主只会为
`trigger_agent=True` 的调用方（也就是定时器）真正开一轮，所以普通系统通知仍然不会吵醒它。
这一轮的提示注入会告诉 Bot：

```
[睡眠状态] 你从 23:00 起一直在睡觉，计划 07:24 自然醒。现在是夜里值班——
有个定时任务把你临时叫起来处理，处理完就继续睡，不用寒暄，也不要表现得像已经起床了。
```

值班不会打断睡眠段（定时器不等于起床），但会按「夜间值班计入时长」记账，
其中一半算作损失的休息，总量封顶为整夜的四分之一。
`block` 策略则回到「只入历史、不执行」。

### 重启

启动时枚举「已有睡眠状态的频道」∪「近 N 天有消息的频道」，逐个对账：

- 睡着且已过计划起床点 → 立刻结算；在宽限期内补发播报，超时则静默结算
- 醒着但当前正处于夜间窗口 → 入睡，且**睡眠段回填到真实就寝点**（不是启动时刻）
- 之后维护循环覆盖所有装载过的频道，不再依赖「有人先说话」

### 睡眠质量

**基准是当晚自己的计划**，不是某个固定时长。起床点本来就是在范围内随机抽的，
拿固定值当基准会让「今晚碰巧抽到 6:50 起」被算成睡得差——那是插件自己掷的骰子，
不是这一夜的质量。所以睡满计划 = 100%，超过 100% 来自「整夜没被打扰」的加分。

```
base    = 100 × min(有效睡眠 / 计划睡眠, 1.25)     有效睡眠 = 实际睡眠 − 0.5 × 夜间值班
       − 6 × (睡眠段数 − 1)                       碎片化，封顶 24
       − 4 × w(t)  每次没被理会的呼叫
       − 10 × w(t) 每次真的把人叫起来的呼叫
       + 3          整夜无人打扰、无中断、无值班时的加分
       + 稳定扰动
w(t)    = 0.35 + 0.65 × sin(π × 进度)^1.2         倒 U：刚睡下与快起床时最便宜，后半夜最贵
```

默认配置下的分数（与随机起床点无关）：

| 场景 | 分数 |
|---|---|
| 一夜无扰 | 101–108 |
| 1 次没理会的呼叫 | 94–101 |
| 3 次没理会的呼叫 | 86–94 |
| 6 次没理会的呼叫 | 75–84 |
| 被叫醒 30 分钟 | 76–85 |
| 被叫醒 2 小时 | 58–67 |
| 只睡了 1 小时 | 20–26 |

想按固定时长评分（例如「不管计划多久，8 小时才算 100%」）就把
**目标睡眠时长**设成非 0。

每次结算都会把 `base / 各项扣分 / 扰动 / 原始分 / 目标时长 / 有效时长` 一起存进
`cycle.quality_breakdown`，分数不对时可以直接看是哪一项，而不用反推。

## 状态机

```
AWAKE ──(到达入睡点)──→ ASLEEP
                          │
              ┌───────────┤
              │           │
     (LLM 判定要叫醒)  (计划起床)
              │           │
              ▼           ▼
        AWAKE_EARLY ──→ AWAKE
              │
   (空闲 / resume_sleep / LLM 判定不需要)
              │
              ▼
           ASLEEP
```

## 开发

```bash
python -m pytest tests -q
```

`tests/hoststub.py` 伪造 `nekro_agent.*`，让接线层（`__init__.py`）可以脱离宿主被测试。
`tests/test_host_contract.py` 用 `ast` 解析真实 NekroAgent 源码校验这些假设没有漂移
（`db_chat_channel` 仍是普通 property、`MsgSignal` 取值不变、`BLOCK_ALL` 仍早于消息落库等）。
它默认找同级目录 `NekroAgent_ByAkiyo` / `nekro-agent`，也可以显式指定；两个版本都应通过：

```bash
NEKRO_AGENT_SRC=/path/to/nekro-agent python -m pytest tests/test_host_contract.py -q
```

`tools/integration_probe.py` 是**上机器用的**：放进 NekroAgent 根目录、用它的 venv 跑，
会连真实数据库、真实 `message_service`、真实人设跑一遍全链路（启动对账、包装闸门、
叫醒协议、结算播报、重启恢复、`/sleep` 指令），但**一条消息都不会发出去**——
所有出站路径在插件被加载之前就被换成了捕获，唯一被驱动的频道是它自己建、跑完自己删的。

```bash
cp tools/integration_probe.py /opt/NekroAgent_ByAkiyo/
cd /opt/NekroAgent_ByAkiyo && uv run python integration_probe.py
```

## 已知未完项

- **夜间值班时长是估算值**：插件拿不到 Agent 轮次的真实耗时（要拿只能猴补丁宿主私有方法），
  所以按「夜间值班计入时长」记一个保守估计，总量封顶整夜的四分之一。
- **`defer` 策略未做**：推迟到起床后执行需要回写定时器队列，属于宿主的活，
  当前只有 `run` 与 `block` 两个诚实的选项。
- **WebUI 面板**：近 7 夜的质量/时长曲线还没做，目前只能靠 `/sleep status` 看当前这一夜。
  （上游有 `webui_path` 构造参数、fork 没有，做的时候要能力探测。）
- **只保留最近一夜的评分明细**：`quality_breakdown` 挂在当前 cycle 上，
  新的一夜开始就覆盖了，没有历史序列。WebUI 要做曲线得先加一份轮转记录。

## 技术要点

- 不修改任何 NekroAgent 核心文件
- 使用 `PluginStore` 持久化，不建表；启动枚举直接查 `DBPluginData` / `DBChatMessage`
- 只包装宿主的一个**公开**方法 `schedule_agent_task`（且仅在 `block` 策略下真正拦截），
  不再碰任何私有方法
- 每个 `chat_key` 独立状态、独立异步锁
- 领域层（`models` / `schedule` / `engine` / `quality`）不导入宿主单例，可独立测试
- `resume_sleep` 通过 `mount_collect_methods` 按状态收集：只有被提前叫醒、且还没到
  计划起床点时才出现在提示词里，白天一个 token 都不占
- 命令系统缺失时（老版本宿主）自动跳过 `/sleep` 注册，插件仍可加载
- 每频道解析出的作息与实例配置带 300 秒 TTL 缓存，写入覆盖时显式失效
- 通过运行时 `getattr` 能力探测兼容两个版本，不按版本号分支
