# NekroAgent 自动睡眠插件

为每个会话提供独立的拟人化睡眠周期，无需修改 NekroAgent 核心代码。

## 功能

- **定时入睡与随机起床**：默认每晚 23:00 静默入睡，次日 06:45–08:30 之间随机自然醒
- **两次叫醒协议**：睡眠中用户有效呼叫→固定提示（不经 LLM）→同一用户再次呼叫→正常唤醒进 LLM
- **静默拦截**：睡眠期间随机回复、主动回复、普通系统消息被完全拦截，不触发 LLM
- **定时任务兼容**：定时任务可临时唤醒执行，完成后自动恢复睡眠，且计入睡眠质量
- **主动睡下**：Bot 可调用 `resume_sleep` 工具重新入睡
- **空闲自动睡回**：被叫醒后无新互动自动静默睡回（默认 10 分钟）
- **睡眠质量统计**：基于连续积分模型计算质量百分比（非固定扣分）
- **自然醒通知**：满足条件时发送角色扮演式起床报告
- **双版本兼容**：同时兼容 Akiyo 版与原版上游 NekroAgent

### v1.1.0 趣味玩法

- **梦境播报**：晨间报告附带一条当夜梦境，睡得越差越容易做噩梦；质量 ≥115 的"神之夜"什么都不记得 😴
- **分档起床状态**：质量决定起床状态——神清气爽 / 睡得不错 / 睡得一般 / 睡得迷糊 / 睡眼惺忪，各配专属吐槽
- **连续睡眠打卡**：自动统计连续好觉天数与比昨晚的起伏，晨间报告带趋势
- **晚安消息**：入睡时按概率（每晚固定种子，重启不会重复）主动说晚安
- **起床气分级**：深夜被叫醒、半夜被叫醒、临近自然醒被叫醒，注入给 LLM 的状态提示不同
- **睡眠报告工具**：Bot 可调用 `get_sleep_report` 查询近 7 天睡眠质量，被问"你最近睡得怎么样"有据可答
- **定时任务计费修复**：夜间定时任务真实计入质量评分（此前该部分从未生效）

## 安装

将 `nekro_auto_sleep/` 目录复制到 NekroAgent 的本地插件目录 `data/plugins/workdir/` 下：

```
data/plugins/workdir/nekro_auto_sleep/
├── __init__.py
├── models.py
├── schedule.py
├── quality.py
├── engine.py
├── persistence.py
├── runtime.py
└── tests/
```

重启 NekroAgent 后在插件管理页面启用「自动睡眠」插件。

## 配置

所有配置项均支持 WebUI 中文界面，在插件设置页面可直接修改：

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| 启用自动睡眠 | `true` | 总开关 |
| 时区 | `Asia/Shanghai` | IANA 时区名称 |
| 入睡时间 | `23:00` | 每日自动入睡时间（HH:MM） |
| 起床时间范围（起始） | `06:45` | 随机起床最早时刻 |
| 起床时间范围（结束） | `08:30` | 随机起床最晚时刻 |
| 起床随机粒度 | `1` 分钟 | 候选起床点间隔 |
| 接近起床判定比例 | `0.15` | 末段比例，提示语切换为「还没起床」 |
| 叫醒确认窗口 | `180` 秒 | 二次叫醒的时间窗口 |
| 历史记录模式 | `preserve` | `preserve`=保留消息 / `strict`=完全拦截 |
| 呼叫关键词 | `醒醒,起床,在吗` | 触发叫醒的关键词（逗号分隔） |
| 默认人格名 | `Bot` | 获取预设名失败时的回退名 |
| 提前叫醒空闲超时 | `10` 分钟 | 被叫醒后无互动的睡回时间 |
| 离线补发宽限期 | `120` 分钟 | 重启后补发自然醒通知的最大延迟 |
| 维护循环间隔 | `15` 秒 | 后台检查间隔 |
| 定时任务等待超时 | `900` 秒 | 插件等待定时任务完成的上限 |
| 睡眠质量下限 | `60` | 质量百分比最低值 |
| 睡眠质量上限 | `120` | 质量百分比最高值 |
| 质量稳定扰动幅度 | `4.0` | 每次质量的随机扰动范围 |
| 晨间梦境播报 | `true` | 晨间报告附带当夜梦境 |
| 晚安消息概率 | `0.35` | 入睡时主动说晚安的概率（每晚固定种子） |
| 无打扰也发晨间报告 | `true` | 关闭后仅在被叫醒过的夜晚发送报告 |
| 质量历史保留天数 | `14` | 用于连续打卡与趋势的天数 |

## 工作流程

### 正常睡眠

```
23:00 → Bot 静默入睡（不发消息）
       ↓ 睡眠期间：群聊普通消息静默拦截
       ↓ 随机/主动回复完全静默
06:45-08:30 → 随机时间自然醒
       ↓ 如有人叫过但未叫醒 → 发送起床报告
       ↓ 无人叫过 → 静默起床
```

### 叫醒流程

```
用户有效呼叫 → 【Bot已经睡了 要叫醒Bot吗？】(不经 LLM)
       ↓ 同用户 3 分钟内再次呼叫
       → 切换为 AWAKE_EARLY，本轮正常进 LLM
       → 注入"你刚刚被用户提前叫醒了"（不写历史）
       ↓ 10 分钟无新互动 → 静默睡回
       ↓ 或 Bot 调用 resume_sleep → 【Bot已睡下】
```

### 接近起床

```
用户呼叫 → 【Bot还没起床 要叫醒Bot吗？】
       ↓ 后续流程同上
```

### 晨间报告示例（v1.1.0）

```
【小A已起床：昨日睡眠质量 96%（睡得不错），睡眠时长 9 小时 12 分钟】
😴 睡了个好觉，皮肤都在发光。
🌙 梦见钱包突然胖了一圈，数钱数到手抽筋
📈 已经连续 3 天睡得不错
```

## 状态机

```
AWAKE ──(到达入睡点)──→ ASLEEP
                          │
              ┌───────────┤
              │           │
         (二次叫醒)   (计划起床)
              │           │
              ▼           ▼
        AWAKE_EARLY ──→ AWAKE
              │
     (空闲/resume_sleep)
              │
              ▼
           ASLEEP
```

## Hook 适配说明（重要）

本插件是"睡眠门卫"型插件：它必须在消息进出 Agent 的必经之路上做拦截与放行，
因此**深度依赖钩子机制**。涉及两层：

### 第一层：NekroAgent 插件框架的标准挂载点（被动回调）

| 钩子 | 挂载方式 | 签名（本插件实现） | 为什么需要 |
|------|----------|--------------------|------------|
| 用户消息钩子 | `mount_on_user_message` | `(ctx, message, *args, **kwargs)` | 睡眠中拦截普通消息（`BLOCK_ALL`）、放行有效呼叫、触发叫醒协议（`FORCE_TRIGGER`） |
| 系统消息钩子 | `mount_on_system_message` | `(ctx, message, *args, **kwargs)` | 睡眠中拦截普通系统消息，同时放行定时任务产生的系统消息 |
| 提示注入钩子 | `mount_prompt_inject_method` | `(ctx, *args, **kwargs)` | 被叫醒瞬间给 LLM 注入起床状态（含起床气分级），不写入历史 |
| 沙盒工具 | `mount_sandbox_method` | `(*args, **kwargs)`（ctx 从首位或 kwargs 取） | `resume_sleep` 主动睡回、`get_sleep_report` 查询睡眠报告 |
| 生命周期 | `mount_init_method` / `mount_cleanup_method` / `on_enabled` / `on_disabled` | `(*args, **kwargs)` | 启停维护循环与运行时包装 |

**签名兼容设计**：框架的事件分发（如 `collector.handle_on_user_message`）没有
try/except 保护，插件 handler 的 TypeError 会直接炸掉整条消息处理链。自 v1.1.1
起，本插件所有钩子 handler 均以 `*args/**kwargs` 收尾——即使上游（如 2.4.x 及
之后版本）扩展了 hook 传参个数，多余参数会被安全吞掉，绝不会再因签名不匹配
导致框架崩溃。沙盒工具则兼容 ctx 位于位置参数或关键字参数两种传法。

### 第二层：运行时方法包装（可逆 monkey-patch，主动 hook）

插件用 `wrap_callable()` 在运行时包装 4 个宿主单例方法（全部 `*args/**kwargs`
透传，不假设参数个数）：

| 被包装方法 | 作用 |
|------------|------|
| `message_service.schedule_agent_task` | **派发层**（必需）：睡眠中且无许可时静默丢弃 Agent 任务 |
| `message_service._run_chat_agent_task` | **执行层**（可选）：执行前复查睡眠状态，第三道门 |
| `timer_service._execute_task` | 定时任务来源标记 + 记录 timer 间隔/租约（计入睡眠质量） |
| `recurring_timer_service._fire_job` | 同上（循环定时任务） |

安全机制：私有标记 `__nekro_auto_sleep_wrapped__` 防重复安装；`__nekro_auto_sleep_original__`
保存原函数，cleanup 时 `unwrap_callable` 完全还原；除 `schedule_agent_task` 外
其余目标均为 `hasattr` 能力探测的可选项，缺失时自动降级。

### 对上游 v2.4.x 的核查结论（2026-09-03）

对官方 `KroMiose/nekro-agent` 的 `v2.4.0`、`v2.4.1` 标签与 `main` 分支逐一核对了
全部插件回调调用点（`collector.py` 的消息/系统消息/注入/生命周期分发，以及
`message_service` 中被包装方法的签名）：**钩子签名与 2.3.x 完全一致，未发现
传参个数变化**。`NekroPlugin.__init__` 的既有参数（`name`/`module_name`/
`allow_sleep` 等）在 2.4 中全部保留。本插件在 2.3.1/2.3.3 宿主实测通过，并已
通过弹性签名适配 2.4 及未来版本的参数扩展。

## 兼容性

- Akiyo 版 NekroAgent (`Akiyo-dayo/NekroAgent_ByAkiyo`) v2.3.3
- 原版上游 NekroAgent (`KroMiose/nekro-agent`) v2.3.1 / v2.4.x

通过运行时 `getattr` 能力探测实现兼容，不按版本号分支。

## 技术要点

- 不修改任何 NekroAgent 核心文件
- 使用 `DBPluginData` / `PluginStore` 持久化，不建表
- 每个 `chat_key` 独立状态、独立异步锁
- Pydantic 严格验证，schema 版本保护
- 领域层（models/schedule/engine/quality）不导入宿主单例，可独立测试
- 包装函数带私有标记，防重复安装，cleanup 时安全恢复

## 许可

与 NekroAgent 保持一致。
